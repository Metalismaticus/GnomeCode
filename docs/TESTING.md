`/studio/check` и субагенты берут их отсюда, а не из памяти.

Канонические ракурсы — что снимается у любого пункта про вид помимо места из
«Как увидеть»: главное окно 1440×900 (тёмная и светлая тема), минимальное
1024×640; состояния «пусто» и «чат с сообщениями».

Как открывается окно — правило для всех команд, которые пишут `/studio/setup` и
исполнители: окно проверки не мешает владельцу работать.
Проверки логики — без окна (`tsc`, `cargo check`, Vitest). Снимки интерфейса —
Playwright в headless-режиме: окна нет вовсе, снимок стабильный; для снимков
«как у владельца» — `npm run tauri dev` на экране, окно владельцу — обычного
размера, с фокусом. `always_on_top` — никогда. Флаги, не проверенные
запуском, — «не проверено: <флаг>».

В контекст чата брать только итоговую строку прогона, а не весь вывод.

## Принято без полной проверки

Пополняет `/studio/done` из строк `Ограничение:` и «вид не проверен»: пункт, дата,
чем ограничено. Запись снимается только ссылкой на проверку, которая это
покрыла.

## Нестабильные проверки

Проверка, красная 1–2 раза из 3 повторов, — сюда: имя, дата, как часто. Продукт
по ней вслепую не чинить — сначала сделать проверку устойчивой.

## Ловушки стека

Неочевидное, на чём уже теряли время. Пополняет `/studio/done` из строк `Ловушка:`
итогов исполнителя; исполнитель читает раздел перед работой.

- Tauri: первый `cargo build` компилирует сотни ящиков — минуты; не мешать,
  не «чинить» по таймауту. Предел быстрой проверки учитывать после первого замера.
- `npm run build` = `tsc && vite build`: ошибка типа падает на `tsc`, до сборки
  не доходит — читать вывод с начала.
- MSVC-сборка (найдено 2026-10-04 при `/studio/setup`): Rust требует
  `link.exe` и Windows SDK; «vswhere находит компонент» ≠ «библиотеки на
  месте» — проверять наличие `VC\Tools\MSVC\<версия>\lib\x64\msvcrt.lib` и
  `Windows Kits\10\Lib\um\x64\kernel32.lib`. Линковка падает честным кодом
  (LNK1104) — это не красная проверка продукта, а неготовое окружение.

## Данные пользователя

Настройки и данные приложения будут жить в `%APPDATA%/GnomeCode`
(папка данных Tauri). Проверки и копии — на отдельной папке через
`GNOMECODE_DATA_DIR`; агенты основную не трогают. Сейчас данных нет.

Агентам трогать их нельзя. `/studio/start` снимает копию перед партией, которая может
их задеть.

## Полигон

Строится пунктом «Построить проверки продукта» (второй пункт очереди):
`tests/checks/` — проверки по одной, `tests/ui/` — UI-сценарии Playwright,
`tests/lib/` — общие помощники, раннер `tools/run_checks.py` находит проверки
сам, без общего списка.

### Правила каркаса

- проверка без единого утверждения — провал;
- ошибка скрипта во время проверки — провал, если её явно не разрешили;
- пропуск — только с причиной;
- пустой вывод или ненайденный инструмент — красное;
- итог перечисляет каждый провал поимённо;
- раннер находит проверки сам: новая проверка — новый файл, без строки в
  общем списке; общие помощники проверок — в одной папке (`tests/lib/`), не
  копиями по файлам;
- у каждой команды предел времени (замер × 3), зависание — красное (код 124).

### Как добавить проверку

Проверка — файл `tests/checks/<имя>.py` (или `.mjs` для UI-сценария): функция
`check()` возвращает (код, итог-строку). Раннер подхватывает файл сам.
Правило: новая проверка должна быть красной без исправления и зелёной с ним —
иначе она ничего не стережёт.

### Красное, которое бывает правильным

Проверку заводят и на открытый баг — тогда она красная намеренно и стережёт
починку. Прежде чем «чинить красное», сверить с `BUGS.md`. Такую проверку
нельзя убирать или ослаблять ради зелёного итога.

### Чего проверки не видят

Живые ответы моделей (нужны ключи и сервер), реальные MCP-плагины, вёрстку
и картинку глазами — это ловится снимком экрана, а вид и ощущение решает
владелец. Числа стерегут числа.

## Бюджет пункта

Пункт не тянется часами. Кроме кругов (не больше трёх на шаг) у него есть
время — чистая работа агентов от начала пункта (время начала — в его строке
`docs/BATCH.md`), без ожидания владельца:

| Размер пункта | Бюджет |
|---|---|
| малый | ~1 ч |
| средний (размер не указан) | ~2 ч |
| большой | ~4 ч |

Размер — строка «Размер:» пункта в «Подробностях» `docs/ROADMAP.md`; нет её
— средний. Числа — выбор проекта, владелец их может поправить здесь.

Стоп без окна — вышел бюджет или два круга подряд без видимого сдвига
(строки «Вижу:» называют тот же главный дефект, менялись только числа): в
первый раз — смена способа, после неё снова без сдвига — пункт
`не выполнен: не уложился — <что видно, что пробовали, чем способ плох>`,
работа — в `rounds/`, строка «Найдено по ходу» для `/studio/idea`; партия идёт
дальше. В отчёте конца запуска такие пункты — первыми, с «Вижу:» последнего
круга и строкой «что предлагаю».

## Параллельная работа

**Состояние: не проверено · пишут: 2 · тяжёлых проверок: 1**

`/studio/start` делает независимые пункты одновременно, каждый в своей копии проекта
(git worktree), только при состоянии «проверено» и `пишут` больше 1. Решает по
пунктам разведчик `scout`; сомнение — по одному.

- `пишут` — сколько пунктов пишется одновременно; 2 — до двух разом.
- `тяжёлых проверок` — сколько полных прогонов и проверяющих со снимками
  идёт одновременно, обычно 1.
- Проверить числа пробным прогоном — `/studio/parallel проверить`.

### Подготовка копии

```bash
npm install                          # зависимости интерфейса
cargo fetch --manifest-path src-tauri/Cargo.toml   # крейты Rust
```

Готово, когда быстрая проверка в свежей копии зелёная — замер: не сделан.

### Набор копий

Копии — `../GnomeCode.wt/slot<K>`, по одной на пишущий пункт; создаются и
переиспользуются по правилам шаблона. `clean` без `-x` не трогает
`.gitignore`-файлы: `node_modules/` и крейты остаются.

### Отдельные данные

- Каждая копия получает свою папку данных: `GNOMECODE_DATA_DIR=<путь копии>/data`.
- Свой `cargo target`: `CARGO_TARGET_DIR=<путь копии>/target` — иначе копии
  дерутся за блокировку `target` (это же и «Нельзя одновременно»).
- Порт dev-сервера и OpenCode server: копия поднимает свои (аргументом порта).

### Общие узлы

Файлы и системы, которые **никогда** не меняют два пункта одновременно:

- `package-lock.json`, `src-tauri/Cargo.lock` — файлы зависимостей;
- `src-tauri/tauri.conf.json` — конфигурация окна и сборки;
- `src-tauri/src/opencode/` — типизированный API-клиент (все от него зависят);
- `src/styles/tokens.css` — токены тем;
- формат хранения настроек и чатов.

### Нельзя одновременно

- `cargo build`/`cargo check` в одной папке без своего `CARGO_TARGET_DIR` —
  блокировка `target`;
- замеры времени запуска — только в основной папке и по одному.

## Замеры

Числа в проекте получают прогоном, а не рассуждением. Что мерится и как —
появится в группе «замеры» полигона (время запуска окна от старта процесса

размер сборки). Пока замеров нет: продукта ещё нет.

Зонд, понадобившийся второй раз, коммитится как проверка.

## Здоровье кода

Держит «Правила кода» `AGENTS.md`: строки «здоровье кода» и «типы» в
«Командах проверки». `tools/code_check.py --changed` — только новое с
последнего коммита, без флагов — весь проект, `--only <файл>` — все строки о
нём без обрезки; находка — строка `уборка: …` с тем, как исправить; заметки
— материал для уборки, не отказ.

- **Типы движка:** включены — `tsc` strict (`tsconfig.json`) и `cargo check`
  входят в быструю проверку; ослабления (`any`, `unwrap()` в новом коде,
  `@ts-ignore`) — по решению исполнителя и с причиной в итоге.
- **Пороги** числами здесь не писать: действующие печатает
  `python -X utf8 tools/code_check.py --limits`; свои — ключ `limits` в
  `tools/code_baseline.json`, менять — пунктом очереди с причиной.
- **База** `tools/code_baseline.json` — каким код был до правила: старое не
  растёт, новое — в пределах. Снижает `/studio/done`, поднимать нельзя; базы нет
  (код 2) — `/studio/setup обновить`.
- **Типы** — блоки своего стека:
  - *TypeScript.* `strict: true`, `noUnusedLocals`, `noUnusedParameters` —
    уже в `tsconfig.json`; `any` и `@ts-ignore` — только с причиной в итоге
    пункта; границы с Rust — типизированные команды Tauri, не сырые `invoke`.
  - *Rust.* `cargo check` чист; ошибки — не `expect()` на пути запроса
    пользователя, а `Result` наружу; состояния — `enum`, записи — `struct`.
