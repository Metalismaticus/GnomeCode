## ADR-0004 — Плагины: каталог, права, установка (Этап 2)

**Дата:** 2026-10-06/07 · **Статус:** принято (партия Этапа 2 принята владельцем)

- **Каталог — JSON-индекс по raw-URL константе** (`CATALOG_URL`), не свой сервис.
  Владелец уточнил (2026-10-07): каталога-репозитория не заводим — `index.json`
  строится в репозитории плагина (сейчас `Metalismaticus/OpenCode_Plagin`),
  плагинов может быть много. Пока index.json не появился, живой путь честно
  показывает «каталог недоступен»; проверка — loopback-фейк.
- **Формат плагина — OpenCode v2** (`export default { id, setup }`); v1-установка —
  однофайловый плагин по raw-ссылке, в папку плагинов движка
  (`XDG_CONFIG_HOME/opencode/plugins`) + реестр `installed.json`.
- **Права:** умолчание категории — ask («Спрашивать при первом использовании»);
  порядок решения вызова: deny правила → грант чата/allow → окно ask; deny
  старше гранта («не спрашиваются никогда»); отказ владельца в окне —
  «requires approval», отказ правилом — «denied». Правила — `rules.json`
  (секция «default» — глобальные умолчания из настроек).
- **Обновления:** тихие (права не изменились), изменившиеся права — сводка до
  включения; владелец выбрал (2026-10-06): сводка прав при обновлении — **окном
  при запуске** (сцена K) — правка к пункту 4 в очереди. Semver-парсер не
  заводился: «новее» = версия отличается (индекс пишет владелец).
- **Скоупы:** Once / чат / проект / глобально — `plugin_scopes.json`; «новый
  чат» проксируется перезапуском окна (сессия движка возобновляется).
- **Tool Sets:** `tool_sets.json` (сеты — не скоупы, файлы систем не смешиваются);
  дефолт проекта — проектный список скоупов; задание дефолта — полоса
  Chat/Project у строки сета (выбор владельца 2026-10-06).
- **Ключи провайдеров:** Windows Credential Manager (`keyring` v3, windows-native);
  ключ на экране не возвращается никогда; проверка — запрос списка моделей;
  рестарт движка после сохранения — тихий.
- **Модель по умолчанию:** `defaultModel` в state.json; панель сравнения — один
  компонент с режимами «для чата» (бейдж) и «по умолчанию» (настройки).
- **Главное окно:** вариант B («уровни поверхностей» + «свечение в цвет
  акцента», тёмная тема) — вырезка совпала с образцом по замеру; логотип в
  сайдбаре — маскот; финальный выбор владельца (2026-10-07): сайдбар — круглый
  значок «гном за ноутбуком» (`owner-2026-10-05-3-icon.png`), он же иконка
  приложения (панель задач); голова-маскот (`4-logo.png`) остаётся в референсах.
- **Окно без рамки:** `decorations: false`; drag-region требует
  `core:window:allow-start-dragging` в capabilities (у `core:default` его нет).

## Уроки партий

Партия 2026-10-06..07 (13 пунктов Этапа 2 + 5 кругов правок по живой копии):

- Живой движок (v2.0.22/23) оборачивает ответы списков в
  `{"location":…,"data":[…]}`, а фейковый движок полигона отдаёт чистый массив —
  живой путь (`plugin_list`, пикер) молча умирал, и это нашёл владелец, а не
  проверка. Правило: **фейковый движок держит форму живого**; расхождение
  «фикстура/фейк — живой движок» — это баг полигона, не продукта.
- Старт окна блокировали два синхронных ожидания (движок в setup до 30 с,
  каталог моделей ~7 с сети): окно появляется только после готовности —
  «окно сразу, тяжёлое — фоном с честной строкой в ленте» стало правилом старта.
- Tauri 2: `core:default` capabilities НЕ содержит `core:window:allow-start-dragging`
  — drag-region молча не работает; смена только иконок не перезапускает
  сценарий сборки — exe линкует старый .res.

Партия 2026-10-04..05 (7 пунктов Этапа 1):

- Движок OpenCode ищется в трёх местах: PATH → папка ресурсов настольного
  OpenCode → `%APPDATA%\ai.opencode.desktop\cli\*` — потому что на машине
  владельца команда `opencode` в PATH отсутствует, а движок есть (адресалитой).
- «Подключение» плагина к чату — запись в реестре нашего приложения
  (`src-tauri/src/plugins/registry.rs`), не вызов сервера: у движка
  `POST /api/plugin` не существует (404), а `/api/plugin` только перечисляет.
- Выполнение команды плагина — через собственный слой прав; посторонам
  у довериться движку нельзя (ADR-0001ddt): вопрос владельца в BLOCKED.md.
- Быстрая проверка продукта — `npm run check`, честный вердикт = код возврата:
  0 зелено, nonzero красное (2 у tsc, 101 у cargo).
- Сама живая модель в проверках не участвует сознательно: изолированный движок
  без авторизации владельца; живое поведение — глазами владельца.

## ADR-0003 — Стек: Tauri + React/TypeScript

**Дата:** 2026-10-04 · **Статус:** принято

Десктоп-клиент — **Tauri 2** (Rust-бэкенд) + **React + TypeScript** фронт.

Обоснование:
- лёгкий дистрибутив и низкое потребление памяти — важно для приложения, живущего рядом с IDE и агентами;
- Rust-бэкенд удобен для управления процессом `opencode serve`, локального реестра плагинов и файловых операций с проверкой прав;
- React/TS — самый богатый экосистемный выбор для сложного UI (чат-лента, дифы, панели).

## ADR-0002 — Бренд и темы

**Дата:** 2026-10-04 · **Статус:** принято

- Имя продукта — **GnomeCode**. Слоган: «Идеи. Код. Результат.»
- Маскот — гном-разработчик (иконка/логотип из ассетов); используется как иконка приложения и аватар агента.
- Две темы: **тёмная** (базируется на референсе «Codexis») и **светлая** (референс «OpenCode PRO»). Единая дизайн-система, обе темы — первоклассные.
- Имена «Codexis» и «OpenCode PRO» в UI не используются — это внутренние имена референсов.

## ADR-0001 — Ядро: GUI-обёртка над OpenCode-сервером

**Дата:** 2026-10-04 · **Статус:** принято

GnomeCode **не пишет собственный агентный движок**. Ядро — запущенный
`opencode serve` (HTTP API OpenCode), с которым GUI общается как клиент:
сессии, сообщения, стриминг событий, tools, permission-запросы.

Следствия:
- agent loop, менеджер tools и MCP-раннер достаются бесплатно и обновляются с апстримом;
- собственные слои GnomeCode — то, чего у OpenCode нет: PluginRegistry, PluginInstaller,
  скоупы подключения (chat/project/global), пресеты проектов, Permission-UI, Usage/Audit;
- «PluginRuntime» из спеки плагинов = тонкий мост над MCP-подсистемой OpenCode;
- риск: зависимость от апстрим-API OpenCode — фиксируем версию и держим анти-коррозионный слой
  (типизированный клиент API в Rust/TS, без размаазывания вызовов по UI-коду).
