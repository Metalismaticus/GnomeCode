# Чеклист ручной проверки обновлений (ET8/ET9)

UI-процесс вкладки Updates не покрыт автотестами (карточки, стек «Обновить
всё», тост) — он проверяется этим чеклистом на fixture-странице
`npm run dev` → `?состояние=плагины-обновления`.

## ET9 — базовый проход

1. [ ] Вкладка Updates открылась автоматически, карточка «Docs · 0.9.0 →
   1.0.0 · ждёт прав» с diff «+ Write: ask — менять файлы проекта».
2. [ ] Бейдж на вкладке Updates показывает «1»; на «Installed» тоже виден.
3. [ ] Клик по вкладке Updates/бейджу фокусирует первую ждущую карточку.
4. [ ] «Обновить» применил обновление: статус «обновлено», реестр на 1.0.0
   (fixture-память), карточка осталась в ченджлоге.
5. [ ] «Оставить текущую» переводит карточку в «отклонено»; повторный вход
   в состояние не возвращает карточку в ждущие (cargo: declined_update_is_
   not_offered_again).
6. [ ] Git и Browser в ченджлоге: «обновлено», версии «от → до».
7. [ ] Консоль чиста, ошибок нет.

## ET8 — «Обновить всё» (стек, F7)

1. [ ] При 2+ ждущих карточках видна кнопка «Обновить всё» (fixture-состояние
   с одной ждущей её прячет — проверено кодом: условие held ≥ 2).
2. [ ] Клик: карточки по очереди «скачивается…» → применяются; тост
   «Обновлено N · ждёт M · ошибок K»; при отказе прав карточка остаётся
   «ждёт прав», остальные применяются (CE-2: независимо).
3. [ ] Cargo-уровень частичного прохождения: applied/held считаются
   независимо (plugin_updates::check_updates_…, declined_update_…).
