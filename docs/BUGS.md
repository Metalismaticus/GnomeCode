# Открытые проблемы

Здесь только **сломанное для пользователя**. Недоделанные функции — в
`ROADMAP.md`, долги владельца — в `BLOCKED.md`. Исправленное отсюда удаляется:
история остаётся в гите, а список, в котором лежит закрытое, перестают
открывать.

Этот файл хранит подробности дефекта, но не определяет его приоритет. Место
бага среди всей работы задаётся короткой ссылкой в разделе «Очередь»
`docs/ROADMAP.md`; полное описание туда не копируется.

Каждая запись по образцу ниже. Первые пять строк обязательны: по ним работает
исполнитель, по последней его проверяют.

- **Симптом** — что видит пользователь, без терминов из кода.
- **Где** — место (экран, действие), при каких условиях и как часто
  повторяется: всегда, иногда, один раз; путь снимка, если есть. Проверяющий
  снимает именно здесь.
- **Причина** — с путями и строками; рядом сказано, чем подтверждена:
  «замером», «по коду, без прогона», «по формуле», «не найдена».
- **Нельзя ломать** — что рядом держится на том же коде и какие проверки это
  стерегут. Без этой строки починка чинит одно и ломает соседнее.
- **Готово, когда** — по чему судим, что дефект закрыт.
- **Мой вариант починки, не обязателен** — только если он прямо следует из
  причины и не трогает соседние системы. Есть сомнения — строки нет.

Решение владельца — не вариант, а указание: пишется отдельной строкой
«Решено владельцем: …» и исполнителем не меняется.

Позже к записи дописываются строки `Замечание владельца во время партии
(<дата>): «…»` (пишет чат замысла) и `Не принят (<дата>): «…»` с путями
снимков (пишет `/studio/done`); их читают исполнитель и проверяющий.

---

- **Симптом** — в настройках сверху дублируются кнопки управления окном
  (свернуть / развернуть / закрыть): два одинаковых набора в одной шапке.
- **Где** — экран «Настройки» (и так же «Плагины»): шапка страницы рендерит
  свой набор кнопок окна поверх общего. Повторяется всегда при открытых
  настройках/плагинах, в обеих темах. Слова владельца (2026-10-08): «в
  настройках дублируются кнопки управления окном сверху».
- **Причина** — по коду, без прогона: `WindowButtons` подключён трижды — в
  общем кластере шапки (`src/components/WindowCluster.tsx:18`, рендерится из
  `App.tsx:150/177`) и отдельными копиями в `src/components/SettingsPage.tsx:112`
  и `src/components/PluginsPage.tsx:145`; на этих экранах общий кластер
  остаётся на месте → дубль.
- **Нельзя ломать** — безрамочное окно: перетаскивание за верхнюю полосу и
  единственный набор кнопок окна на каждом экране при любой ширине
  (узкая раскладка кластер прячет — «один узел, два дома», WindowCluster);
  проверки UI-снимков окон (`tests/ui/window_shot.mjs` и соседние).
- **Готово, когда** — на «Настройках», «Плагинах» и чате ровно один набор
  кнопок окна; узкое окно по-прежнему без кнопок в чате; снимки обеих тем
  зелёные.
- **Мой вариант починки, не обязателен** — убрать `<WindowButtons />` со
  страниц (`SettingsPage`, `PluginsPage`), кнопки окна остаются только в
  `WindowCluster`; если страницы рисуют свою полосу ради перетаскивания —
  заменить на `data-tauri-drag-region` без кнопок.
