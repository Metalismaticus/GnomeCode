# Сценарий: Система плагинов GnomeCode

> Спека и пользовательский сценарий фичи «Plugin System & Chat-Level Plugin Attachment».
> Дизайн-референсы: тёмная тема Codexis (главный экран, активный чат, Security concept)
> и светлая тема OpenCode (чат + правая панель инструментов/безопасности).
> Статус: спека утверждена, реализация не начата.

---

## 1. Цель

GnomeCode даёт плагинам «первоклассный» опыт по образцу Claude Code, но проще и заметнее:

- плагин ставится **один раз** в GnomeCode;
- затем подключается **выборочно** к отдельным чатам или проектам;
- пользователь **не редактирует конфиги вручную** в обычном сценарии.

Целевой сценарий мышления пользователя:

> «Мне нужен GitHub в этом чате» → `+` → Connect plugin → GitHub.

Никаких JSON, командной строки и перезапусков.

---

## 2. Сцены пользователя (сценарий)

### Сцена A. Установка плагина — раздел «Плагины»

Открывается из главной левой навигации. Вкладки:

- **Installed** — установленные
- **Available** — доступные из каталога
- **Updates** — доступные обновления
- **Disabled** — отключённые

Карточка плагина показывает:

| Поле | Пример |
|---|---|
| Название | GitHub |
| Иконка | логотип плагина |
| Описание | «Repository, issues, pull requests» |
| Автор | автор расширения |
| Версия | 1.4.2 |
| Возможности | issues, PR, поиск по коду |
| Требуемые права | сеть: api.github.com; запись: ask |
| MCP/инструменты | список экспонируемых tools |
| Статус обновления | актуальна / доступна 1.5.0 |

Действия над карточкой: **Install · Update · Disable · Uninstall · Configure**.

### Сцена B. Подключение из чата — меню «+»

Кнопка **«+»** в композере чата открывает компактное контекстное меню:

```
+ Add
─────────────────────────
Attach file
Attach folder
Attach image
Add project context

Connect plugin          ← ключевой пункт
Connect MCP server

Web access
Terminal
Other tools
```

### Сцена C. Выбор плагина — searchable list

Пункт **Connect plugin** открывает список **уже установленных** плагинов:

```
Connect plugin
──────────────────────────────
Search plugins...

✓ GitHub      Repository, issues, pull requests
  Blender     Control Blender and inspect scenes
  Godot       Run project-specific Godot tools
  Browser     Browser automation
  Russian Law Legal search tools
  PostgreSQL  Database tools
──────────────────────────────
Browse plugins...     ← открывает каталог (см. сцену F)
```

Клик по плагину → он **немедленно** доступен текущему чату:

- без перезапуска,
- без правки конфигов,
- без ручной регистрации tools.

Внизу списка — **Browse plugins...**: внутренний браузер плагинов. После установки
из каталога сразу предлагается **«Connect to this chat now»** — пользователь не
покидает сценарий разговора.

### Сцена D. Кнопки плагинов в шапке чата

> Слова владельца: «в нашем приложении кнопки подключенного плагина выводятся
> над чатом (красиво и удобно)»; про клик: «применяет эту команду, на которую нажали».

Шапка активного чата показывает подключённые плагины компактными **кнопками**:

```
GLM-5.3 High   [GitHub] [Godot] [Browser]
```

- Кнопка — не просто индикатор: клик **исполняет команду**, которую она
  представляет (обычный путь через permission layer, вызов виден в ленте как tool).
- [решено 2026-10-05] Плагины — формата OpenCode («мы же его по сути
  модифицируем»); кнопки в шапке = **команды, объявленные плагином** (как
  `/studio/*` у studio-плагина); при переполнении — «+N».
- Клик по области бейджей (не по кнопке) открывает панель:

```
Plugins in this chat
──────────────────────────
GitHub        Enabled
Godot         Enabled
Browser       Enabled
PostgreSQL    Disabled
──────────────────────────
+ Add plugin
```

Плагин снимается с чата без деинсталляции.

### Сцена E. Скоуп подключения

При подключении через «+» плагин по умолчанию включается **только для текущего чата**.
Позже пользователь может повысить скоуп:

| Скоуп | Поведение |
|---|---|
| **Once** | действует до конца текущего запроса |
| **This chat** | по умолчанию при подключении через «+» |
| **This project** | доступен всем чатам проекта |
| **Global default** | предлагается во всех новых чатах |

Дополнительные действия: «Keep enabled for this project», «Enable by default».

Это защищает от того, чтобы каждый разговор автоматически получал все установленные инструменты.

### Сцена F. Избранное и недавнее

Часто используемые плагины можно **закрепить (pin)**. В меню «+ → Connect plugin»:

- **Pinned** — сверху списка
- **Recent** — недавно подключавшиеся
- **All installed** — полный список

Цель: подключить привычный инструмент за **≈ два клика**.

### Сцена G. Пресеты проекта

Проект может определять свой набор плагинов. Пример:

```
Проект: VoxelWorld

Default plugins:  Godot · GitHub · Blender
Optional:         Browser · Image tools
```

- Новый чат внутри VoxelWorld → пресет подключается **автоматически**.
- Пользователь всегда может убрать любой плагин из чата.

### Сцена H. Первое включение — сводка прав

Установка плагина **не** даёт ему безлимитных прав. Плагин декларирует
запрашиваемые возможности. Перед первым включением показывается сводка:

```
GitHub wants access to:

✓ Internet: api.github.com
✓ Read repository information
? Modify repositories
? Create pull requests

[Allow for this project]  [Customize]  [Cancel]
```

Пример декларации GitHub-плагина:

| Категория | Значение |
|---|---|
| Network | `api.github.com` |
| Repository access | только разрешённые репозитории |
| Write | Ask |
| Create pull request | Ask |
| Delete repository | **Denied** |

### Утверждённый UX одобрения (решение владельца, 2026-10-05)

Режим **«Спрашивать при первом использовании»**:

- сводка прав — при первом включении плагина (сцена H);
- чувствительный вызов инструмента — компактное окно:
  `[Разрешить] [Разрешить для этого чата] [Отказать]`;
- отказ — строка `⚠ GitHub · Push requires approval` в ленте, вызов не идёт;
- выбор «для этого чата» запоминает правило на чат; «для проекта» — из
  этого же окна; глобальные правила — только вручную в настройках плагина;
- «Right»-действия, объявленные Denied в декларации, не спрашиваются никогда.

### Сцена I. Безопасность на уровне чата

Плагин, подключённый к чату, **наследует политику безопасности этого чата**.

```
Chat security:  Project only
Plugin:         Godot
→ Godot может читать файлы только внутри разрешённых директорий проекта.
```

**Инвариант:** плагин никогда не может обойти ограничения GnomeCode
на файловую систему, терминал, сеть или секреты.

Все вызовы tools проходят через обязательный конвейер:

```
AI
↓
GnomeCode Permission Layer
↓
Plugin / MCP
↓
External resource
```

### Сцена J. Активность плагинов в ленте

Вызовы tools плагинов рендерятся так же компактно, как остальные tools:

```
✓ GitHub · Read issue #241
✓ Godot · Ran project
✓ Blender · Inspected scene
⚠ GitHub · Push requires approval
```

Клик раскрывает детали. Системы **Usage** и **Audit** фиксируют,
какой плагин сгенерировал каждый вызов.

### Сцена K. Автообновление плагинов при запуске

> Слова владельца: «обновляется он сам автоматически с гитхаба
> (когда там есть обновление, при запуске)»; режим: тихо (без вопросов).

При запуске GnomeCode проверяет GitHub и **молча** обновляет установленные плагины.

- Обновление происходит без действий пользователя; версия и изменения видны
  в карточке плагина (вкладка Updates раздела «Плагины»).
- Если новая версия меняет запрашиваемые права — перед включением показывается
  сводка прав (сцена H), как при первой установке.
- Источник обновлений — репозиторий плагина на GitHub
  ([допущение] установка плагинов тоже идёт с GitHub — репозитории/релизы).

## 3. Архитектура

Разделить discovery, установку и исполнение — слои не связаны жёстко:

| Слой | Ответственность |
|---|---|
| **PluginRegistry** | централизованный реестр установленных плагинов, метаданные, версии |
| **PluginInstaller** | установка / обновление / удаление из каталога и локальных источников |
| **PluginRuntime** | запуск плагина, жизненный цикл, exposes MCP/tools в чат |
| **PluginPermissionManager** | декларации прав, диалоги согласия, enforcement политики чата/проекта |
| **PluginUI** | раздел «Плагины», меню «+», бейджи чата, каталог, пресеты проекта |

Поддерживаются два типа плагинов:

1. **GnomeCode-native**
2. **OpenCode-совместимые / MCP-интеграции**

## 4. Дизайн-референсы

Утверждённые референсы лежат в `docs/refs/`. Правила:

- сохранять философию раскладки и иерархию информации референсов;
- **не** превращать продукт в generic IDE-dashboard;
- при расхождении реализации с макетом сохранять usability и архитектурную
  целостность, а не слепо воспроизводить AI-сгенерированные детали референса;
- использовать приложенные иконку и логотип приложения (гном-разработчик).
