# Главное окно: три колонки и две темы

Пункт 4 партии (2026-10-05, круг 1/3). Пункт очереди: **[ui] [этап 1] Три колонки
по референсам + две темы** (`docs/ROADMAP.md`, раздел «Подробности ближайших
пунктов»).

Спецификация описывает один экран: главное окно GnomeCode. Исполнитель реализует
буквально, проверяющий сверяет снимок.

- **Образец:** `docs/refs/INDEX.md` — главный образец **не выбран** (строки
  «Не выбран», таблица «Темы» пуста), файлов референсов в `docs/refs/` нет.
  Значит сверять снимок «с референсом» нечем: сейчас образцом для раскладки и
  иерархии служит `docs/DESIGN.md` (разделы 1, 4, 5) плюс уже принятый каркас
  `shots/main-window-1440x900.png`. Это техническое решение исполнителя, не
  вкусовое: ждать референсов пункт не может, критерий закрывается по `DESIGN.md`.
- **Правила:** `docs/DESIGN.md` — характер, цвет, типографика, сетка, раскладка,
  состояния. Все значения — из `src/styles/tokens.css`.
- **Что уже есть:** `src/App.tsx` (три колонки, переключатель темы, композер,
  лента), `src/styles/app.css`, `src/styles/tokens.css` (обе темы заполнены),
  фикстура ленты `src/fixture.ts`, снимок `npm run shot`
  (`shots/main-window-1440x900.png`, `shots/main-window-1024x640.png`).
  Готовых компонентов нет: таблица «Готовые компоненты» (`DESIGN.md`, раздел 8)
  пуста. Значит всё ниже — новое, и правило «нового компонента не заводить,
  пока не показано, что готовые не подходят» отменяется пустотой таблицы.

## Зачем экран

Пользователь открывает приложение и за **три секунды** должен понять: вот
проекты, вот чаты, вот что приложение знает о проекте, вот куда писать.

**Главное действие экрана одно:** написать сообщение модели в чате. Всё,
что помогает это сделать, — крупнее и контрастнее; остальное тише.

**Вторично и потому тише:** список проектов и чатов (слева) — навигация;
«Контекст проекта» (справа) — справка, что приложение уже знает.

**Ядро экрана — центр.** Ширина сайдбара и правой панели фиксированы, тянется
только чат.

## Иерархия (что видно первым, что вторым, что третьим)

1. Композер внизу центра — он всегда на виду, это приглашение к действию.
2. Пустое состояние чата по центру ленты: заголовок → подсказка → три карточки-сценария.
3. Шапка чата: название чата слева, бейдж модели и переключатель темы справа.
4. Сайдбар: логотип, главная кнопка, разделы «Проекты»/«Чаты».
5. Правая панель: заголовок, разделы «Проект» / «Инструменты» /
   «Безопасность этого чата», строки «метка — значение».

**Акцентных пятен на экране ровно два** (`DESIGN.md` §1): главная кнопка
«+ Новый проект» в сайдбаре и активный чат в списке чатов. Логотип, аватар и
«+» в композере сегодня залиты `--accent-gradient` — это третье, четвёртое и
пятое пятно, и они тяжелее главной кнопки. **Решено:** акцент-градиент
остаётся только у главной кнопки и активного чата; логотип, аватар и «+» в
композере — приглушённые (`--bg-panel-2` / `--border`, цвет `--text`).
Иначе «спокойный» характер из `DESIGN.md` §1 не выполняется, а это первое, по
чему владелец судит о виде.

### 1024×640 — минимум

`DESIGN.md` §5: «При ширине < 1200 px правая панель складывается в кнопку».
Сейчас этого нет: на снимке 1024×640 правая панель занимает 280 px, из 1024
остаётся 504 px чата — сжато, композер упирается. **Решено (техника, нет в
`DESIGN.md`):** при ширине < 1200 px правая панель прячется и открывается
всплывающей поверх чата по кнопке в шапке; сайдбар сужается с 240 до 200 px
(«не уже 200 px» — граница из `DESIGN.md`), но не прячется. У `DESIGN.md` нет
правила про ширину сайдбара в этом диапазоне, кроме нижней границы 200 px;
промежуточных значений нет, поэтому взяты границы из документа.

```
┌────────────┬────────────────────────────────────────┐
│ 200 px     │ тянется (824 px при 1024)              │
│            │ Новый чат      [GLM-5.3 High] [☰][☀]   │
│ [G] Gnome… │ ────────────────────────────────────── │
│ + Новый    │                                        │
│   проект   │        лента                           │
│ Новый чат  │                                        │
│ ПРОЕКТЫ …  │ ┌────────────────────────────────────┐ │
│ ЧАТЫ …     │ │ +  Напишите сообщение…           ↑ │ │
│            │ └────────────────────────────────────┘ │
│ [Г] Владе… │ Enter — перенос · Ctrl+Enter — отпр.   │
└────────────┴────────────────────────────────────────┘
```

**Что переносится, что прячется при 1024×640:**

| Что | 1024×640 |
|---|---|
| Сайдбар | 200 px, подпись логотипа «GnomeCode» усекается до «Gnome…» с «…» |
| Правая панель | скрыта, открывается оверлеем 280 px от правого края по кнопке `☰` |
| Переключатель темы | остаётся в шапке, но с иконкой без подписи? **Нет** — подпись «Светлая»/«Тёмная» остаётся: 11 px текст, места хватает (см. снимок) |
| Бейдж модели | остаётся; при нехватке места усекается с «…», не переносится |
| Три карточки пустого состояния | в одну колонку (при 640 px по высоте места мало), карточка во всю ширину ленты |
| Лента | без изменений, только уже |
| Композер | без изменений; подсказка под ним остаётся, но при высоте < 560 px скрывается (место важнее подсказки) — **моё, нет в `DESIGN.md`** |
| Правая панель на 1024 | оверлей: `position: absolute` справа, ширина 280 px, `--bg-panel`, рамка слева, без тени (`DESIGN.md` §7: тени только у всплывающих меню «+» — оверлей не меню, тени нет), закрывается по `Esc`, по клику вне и по кнопке |

## Клавиатура

Десктоп, геймпада нет. Порядок обхода `Tab`:

1. `+ Новый проект` → 2. `Новый чат` → 3. список проектов (по строкам) →
4. список чатов → 5. `Владелец` → 6. переключатель темы →
7. кнопка `☰` (только при ширине < 1200 px) → 8. бейдж модели **не фокусируется**
(не действие) → 9. поле ввода (`Ctrl+Enter` — отправить, `Enter` — перенос) →
10. `+` в композере → 11. `↑` отправить (в выключенном состоянии — в обход не
попадает, но фокус получает: `title` объясняет почему)

`Shift+Tab` — обратно. `Esc` — закрыть оверлей правой панели. Фокус виден
всегда (`:focus-visible`, обводка 2 px `--accent`, смещение 2 px), фокус с мыши
обводку не рисует. Лента не фокусируется: она не интерактивна, а длинный чат с
100 строками иначе утаптывает клавиатуру.

## По чему судить снимок

1. **Три колонки, ширины из `DESIGN.md` §5:** при 1440×900 сайдбар 240 px,
   правая панель 280 px, чат тянется; при 1024×640 сайдбар 200 px, правой
   панели в кадре нет, а в шапке чата есть кнопка `☰`. Доли измеряются
   линейкой по пикселям, не на глаз.
2. **Акцентных пятен ровно два** в кадре 1440×900: главная кнопка «+ Новый
   проект» и активный чат в списке чатов (когда чатов нет — вторая точка не
   требуется, но и лишних нет). Логотип «G», аватар «Г» и «+» в композере
   акцентом **не** окрашены.
3. **Тёмная и светлая темы совпадают по раскладке, различаются по цвету.**
   Сравнить `shots/main-window-1440x900.png` и `shots/main-window-1440x900-light.png`:
   ни одна граница, ни один отступ, ни один размер шрифта не сдвинулись; светлая
   тема не выглядит инверсией с «вывернутыми» рамками.
4. **Пустое состояние** (`shots/main-window-1440x900-empty.png`): заголовок,
   подсказка и три карточки стоят **по центру ленты** по вертикали и по
   горизонтали, заголовок 20 px (не 28), карточки в один ряд на 1440 и в одну
   колонку на 1024.
5. **Насыщенность:** размеры шрифтов из таблицы §3 — 15/14/13/12/11 px и моно
   12 px; нигде нет числа вне таблицы (сейчас есть 16 px у логотипа и 28 px у
   заголовка пустого состояния — оба приводятся к 15 и 20).
6. **Ни одного сырого цвета вне `src/styles/tokens.css`** (проверяется грепом по
   `src/`), обе темы заполнены целиком: переключение «☀ Светлая» меняет фон,
   панели, рамки, текст и акцент на всём окне разом, без перезапуска.
7. **Композер:** «+» и «↑» — 32×32 px, оба прижаты к низу поля; подсказка под
   композером — 11 px, `--text-faint`. Кнопка «↑» при пустом поле выключена и
   выглядит выключенной (нет акцента).
8. **Правая панель:** три раздела разделены 1 px рамками `--border`, строки
   «метка — значение», значение не переносится; на 1024 открывается оверлеем по
   `☰` (`shots/main-window-1024x640-panel.png`) без тени и без горизонтального
   скролла.
9. **Переполнение** (`shots/main-window-1440x900-long.png`): длинное имя
   усечено с «…», длинный абзац перенесён по словам, лента прокручивается, а
   шапка и композер остались на месте; горизонтального скролла нет нигде.
10. **Никаких теней на панелях** — `--shadow` только под всплывающим меню «+»,
    которого в этом пункте ещё нет (`DESIGN.md` §7).
