правки чужих сообщений, ветвление (их в окне и нет); шапка, композер, сайдбар,
приветственная сборка — свои пункты партии.

## 1. Зачем экран

Пользователь читает ответ модели и пишет следующий вопрос — главное действие
одно, и ему принадлежит экран. Всё служебное (как модель работала, откуда
ответ) — второй план: тихие строки внутри хода. Сейчас разговор читается
«коробками»: вопрос заперт в пузыре, ответ размечен плитками на каждый
заголовок, бегущая работа мигает знаком. Цель: разговор — текст на чистом
листе с воздухом, разметка отвечает уровням (заголовок крупнее абзаца,
таблица — таблицей), а работа модели видна живой строкой («думаю / читаю
файл…»), не мигающей заглушкой.

## 2. Что сейчас — кадр «было»

Состояние кода на main (после пунктов 1–2 партии; `Feed.tsx/.css`,
`markdown.ts`, `CodeBlock`, `StepSection`):

| Зона | Сейчас («было») |
|---|---|
| Вопрос | пузырь справа: подложка `--bg-panel-2`, рамка 1 px, радиус 16, ширина ≤ 75 % колонки; подписи нет |
| Ответ | markdown-lite: **любой** заголовок — нумерованная плитка-ступень; список — плоские строки с «•», без нумерации и вложенности; таблиц, цитат, строчного форматирования (жирный, код, ссылки) нет |
| Код-блок | тёмная плашка, подсветка, «Копировать» — уже есть (критерий пункта) |
| Работа модели | бегущий вызов — «⧗» с пульсом знака; пустой ответ до первого кусочка — мигающее «…» |
| Подписи | над репликами пусто; время в ленте не показывается никому |

## 3. Раскладка

Каркас не меняется (DESIGN §5, база §3): лента живёт в центре ChatView,
колонка чтения 760 px по центру (`--feed-column`), на 1024×640 — во всю
ширину центра; композер — на той же колонке. Меняется только анатомия строки.

Блок реплики — подпись + текст, оба на колонке чтения:

```
┌──────────────────────────────── 760 ──────────────────────────────┐
│ Вы · 14:32                          ← подпись 11 px --text-faint  │
│ Посмотри структуру проекта…         ← текст 14/1.5 --text        │
│                                                                  │
│ (12) GLM-5.3 High · 14:33                                        │
│ Смотрю структуру папки…             ← ответ: markdown §5         │
│ ✓ read · src/bridge.ts ▸            ← работа: §6, тихая строка   │
│ SOURCES USED [bridge.ts]            ← источники: база §8, без изменений
└───────────────────────────────────────────────────────────────────┘
```

- Реплика — чистый текст без плашек, рамок и заливок: воздух сам делит
  разговор. Это верно и для вопроса, и для ответа — различает их подпись.
- Строки работы (вызовы, служебные, ошибки) — без подписей: подпись стоит
  только над репликой владельца и репликой модели.
- «Ответ модели получен» и ошибки движка — как в базе §7 (красное — целиком).

## 4. Ритм и подписи

Все числа кратны 4; значения — токены.

| Что | Значение | Было | Откуда |
|---|---|---|---|
| Подпись над репликой | 11 px / 400, `--text-faint`, не caps; до своего текста 4 px (`--space-1`) | нет | **моё, нет в DESIGN §3**: кегль и роль — из таблицы («подпись, число 11–12»),caps не беру — «GLM-5.3 High» капсом искажается. Привести §3 при `/studio/done` |
| Текст реплики | 14 px / 1.5, `--text`, во всю колонку | так же (ответ) | §3 базы; у вопроса плашка убирается |
| Вопрос → первая строка хода | 12 px (`--space-3`) | 8 | **моё**: воздух между репликами — кусок пункта; внутри хода шаги стоят по-прежнему 8 |
| Шаг → ответ | 12 px (`--space-3`) | 8 | там же |
| Между ходами (вопрос → вопрос) | 32 px (`--space-6`) | 32 | §4 базы, без изменений: ходы разделены заметно сильнее строк внутри |
| Состав подписи | «Вы · 14:32» у вопроса; «{модель} · 14:32» у ответа | нет | **моё**: имя второй стороны — имя модели чата, второе имя в окне не заводится; аватаров нет |
| Время | сегодня — «14:32»; раньше — «9 окт, 14:32» | нет | **техника**: тот же формат, что у сравнения (`compare.ts`, MONTHS) — одно место знания о времени |
| Пузырь вопроса | **удаляется** — класс `feed__row--user` остаётся на строке (контракт проверки), блочная геометрия пузыря — нет | пузырь | кусок «убрать „коробки“-пузыри»; DESIGN §4 «радиусы… пузыри сообщений» правится при `/studio/done` |

Ход — по-прежнему строки от вопроса до следующего вопроса (разбиение
`sourceBlocks` не трогается). Подпись — часть строки реплики, не отдельная
строка ленты: пустых подписей «висит в воздухе» не бывает.

## 5. Полный markdown

Разбор ответа (`src/markdown.ts`) расширяется; вид каждого блока:

| Блок | Вид |
|---|---|
| Абзац | 14/1.5, `--text`; блоки ответа разделяются 8 px (`--space-2`); перенос длинного слова — `anywhere`, горизонтального скролла нет |
| Заголовок `#`/`##` | открывает нумерованную сворачиваемую ступень — `StepSection` без изменений: плитка номера, заголовок 14/600 (было 13/600 — **моё**: заголовок ответа читается крупнее меток), развёрнута по умолчанию, клик сворачивает |
| Заголовок `###` | подзаголовок 13/600 `--text` («заголовок раздела» §3), отступ 16 сверху / 4 снизу |
| `####`–`######` | 12/600 `--text-dim`, отступ 12 / 4 (**моё**: ступень каждой глубины — не «полный markdown», уровни должны различаться) |
| Список маркированный | маркер «•» висит на строке, текст с отступом; маркер `--text-dim`; зазор пунктов 4 px (`--space-1`) |
| Список нумерованный | «1.» — число моно 12 `--text-dim`, тот же отступ, что у маркера |
| Вложенный список | сдвиг 16 px (`--space-4`) на уровень, маркер/номер свои |
| Таблица | рамки 1 px `--border`; шапка — 11 px caps `--text-faint` на `--bg-panel-2`; ячейки 13/1.5, паддинг 4×8 (**моё**: плотнее абзаца, крупнее подписи — размер 13 есть в системе); таблица шире колонки — **горизонтальная прокрутка внутри таблицы**, лента остаётся вертикальной (**моё, исключение из §6 «скролла нет»**: перенос по клеткам разрушил бы данные; ползунок — глобальные токены тем). Привести DESIGN §6 при `/studio/done` |
| Код-блок | `CodeBlock` без изменений: тёмная плашка в обеих темах, подсветка токенами, «Копировать» в шапке, видимый без наведения, перенос длинной строки внутри плашки |
| Строчный код | моно 12, фон `--bg-panel-2`, паддинг 0×4, радиус 6 (`--radius-sm`) |
| Жирный / курсив | 600 / italic, цвет текста |
| Ссылка | `--accent` с подчёркиванием; наведение — подчёркивание убирается (**моё**: ссылка — действие, акцент §2 разрешён; на кадре «разбор» ссылок нет, акцентных пятен остаётся два); открывается в системном браузере, не в окне; href без http(s) — не ссылка, а текст |
| Цитата | линия слева 2 px `--border-strong`, отступ текста 12 px, `--text-dim` |
| Разделитель `---` | линия 1 px `--border`, отступы 16 px |
| HTML из ответа | показывается текстом, не исполняется — ответ модели не код окна (безопасность) |

Ступени «1 …» / «2 …» с номерами и сворачиванием остаются — базовая вещь обоих
кадров владельца («нумерованные ступени… сворачиваются», светлый паспорт).
«Полный markdown» здесь значит: глубина заголовков различается, остальная
разметка рендерится, а не съедается.

## 6. Живой прогресс ступеней

Кусок: «думаю / читаю файл…» вместо мигающей заглушки. Строка работы
показывает, **что** происходит, словами; знак-статус остаётся у завершённых.

| Строка | Было | Стало |
|---|---|---|
| Ход без содержимого (пустая строка ответа до первого кусочка) | «…» | тихая строка **«Думаю…»** — моно 12 `--text-dim`, хвостовое многоточие медленно пульсирует (та же анимация `feed-pulse`, прозрачность 0.5↔1, ~1.2 с); исчезает, как только в ходе появился текст или шаг |
| Бегущий вызов («⧗ read», «⋯ read · src/bridge.ts») | «⧗» пульсирует | **«Читаю src/bridge.ts…»** — глагол + деталь строки + живое многоточие; знак ⧗/⋯ на бегущей строке больше не рисуется (кусок: «вместо мигающей заглушки»); детали нет — только глагол «Читаю…», файл не выдумывается |
| Глагол по имени вызова | нет | таблица в одном месте: read «Читаю», grep/glob «Ищу», list «Смотрю», bash «Запускаю», edit «Правлю», write «Пишу», webfetch «Открываю», task «Поручаю»; неизвестное — имя как есть: «todo…» (**моё**: глагол — перевод строки, не выдумка: вызов с таким именем правда идёт) |
| Команда плагина («⧗ docs · search») | «⧗» пульсирует | «docs · search…» — текст строки без знака, живое многоточие; глаголов для команд нет — их пишет автор плагина |
| Завершённый вызов («✓ …») | тихая строка | без изменений — база §7: знак ✓ `--success`, чеврон у строк с деталями, раскрытие кликом/Enter |
| Отказ («⚠ …», «✗ …») | ⚠ — warn, ✗ не тонирован | ⚠ — `--warning`; ✗ — `--danger` (**техника**: живой мост шлёт «✗» на провал — `client.rs::tool_line`, знак тонирован как отказ) |
| Ошибки движка, «Ответ модели получен» | — | без изменений (база §7) |

Состояние «ступени показывают состояние» — это и есть таблица выше: бегущая
строка отвечает на «что сейчас», завершённая — «что сделано», отказ — «что
не вышло». Клик и клавиатура бегущих строк — как у базы: раскрытие деталей
только у строк с известными данными, выдуманных деталей нет.

## 10. Тексты (дословно)

- подпись вопроса: `Вы`, далее `·` и время: `Вы · 14:32`
- подпись ответа: имя модели чата: `GLM-5.3 High · 14:33`
- время: сегодня `14:32`; раньше `9 окт, 14:32`
- прогресс: `Думаю…`; по вызовам: `Читаю…`, `Читаю src/bridge.ts…`, `Ищу…`,
  `Смотрю…`, `Запускаю…`, `Правлю…`, `Пишу…`, `Открываю…`, `Поручаю…`;
  неизвестный вызов — `{имя}…`; команда плагина — `{плагин} · {команда}…`
- завершённые шаги: текст строки без изменений (`✓ read · src/bridge.ts`),
  `title` строки `Детали вызова`
- служебные и ошибочные строки: `Ответ модели получен`,
  `Сервер OpenCode недоступен, перезапускаю…`, `Сообщение не ушло…` — без изменений
- код-блок: `Копировать` / `Скопировано`, подпись языка — без изменений

## 11. Порядок обхода с клавиатуры

Шапка (бейдж модели → «⋯» → тема → кнопки окна) → лента по порядку потока:
ступени ответа (Tab до заголовка, Enter — свернуть) → строки работы с
деталями (Enter/пробел — раскрыть) → ссылки текста → «Копировать» код-блоков
→ чипы источников → «+» → поле ввода → пилюля модели → «↑» (когда видна).
Подписи, бегущие строки и таблица фокус не получают (не действия); таблица
прокручивается стрелками, когда фокус внутри её обёртки. Оверлеи — как в базе.

## 13. По чему судить снимок

1. Реплики — чистый текст на колонке ≤ 760 px по центру: ни плашек, ни рамок,
   ни пузырей; над каждой репликой подпись 11 px приглушённая:
   «Вы · 14:32» / «GLM-5.3 High · 14:33».
2. Воздух читается ступенями: ходы 32, реплика → работа → ответ 12, строки
   шагов 8; подпись стоит вплотную (4) к своему тексту.
3. Заголовки ответа: `##` — нумерованная ступень с плиткой и «▼», сворачивается
   кликом; `###` — подзаголовок без плитки; уровни различаются глазом.
4. Списки: маркер висит, нумерованный — числами, вложенный сдвинут на 16 px.
5. Таблица: рамки 1 px, шапка caps на приглушённой плашке; шире колонки —
   ползунок внутри таблицы, сама лента вертикальна.
6. Код-блок: тёмная плашка, подсветка, «Копировать» виден без наведения.
7. Работа модели: завершённые шаги — тихие «✓ …» с чевроном; бегущая — словами
   («Ищу…», «Читаю src/bridge.ts…») с многоточием, знака ⧗ на ней нет.
8. Ссылка — акцентная с подчёркиванием; в кадре «разбор» акцентных пятен в
   центре по-прежнему два: бейдж модели и кнопка отправки.
9. Тёмный и светлый кадры совпадают по раскладке, различие — только токены;
   ни одного сырого цвета вне `tokens.css`.
10. 1024×640: колонка во всю ширину центра, подписи и таблица не ломаются;
    пустой чат — сборка без изменений.

## 14. Решено за вас

| Что | Решение | Почему | Чем обойдётся, если неверно |
|---|---|---|---|
| **[видно]** Вопрос — тоже чистый текст без пузыря; различие реплик — подпись «Вы» / модель | плашка, рамка и правое выравнивание удаляются у обеих сторон | кусок «убрать „коробки“-пузыри» не делит реплики на своих и чужих; у Клода различает подпись, не коробка | вернуть пузырь вопроса — один CSS-блок `feed__row--user` |
| **[видно]** Заголовки `#`/`##` — нумерованные ступени, `###`+ — подзаголовки | уровни различаются, ступени с номерами остаются | «полный markdown: заголовки» требует уровней; ступени разбора — базовая вещь обоих кадров владельца | все уровни ступенями (как было) или все заголовками — правка разбора в одном месте |
| **[видно]** Бегущая работа — словами с живым многоточием, без знака ⧗ | «Думаю…», «Читаю файл…» | кусок 4: «вместо мигающей заглушки»; пульс знака — она и есть заглушка | вернуть знак — модификатор строки |
| **[видно]** Подпись ответа — имя модели чата, вопроса — «Вы» | без аватаров и вторых имён | аватаров владелец не звал; модель у окна одна | подставить имя агента, когда движок станет их отдавать, — одна строка |
| **[техника]** Время реплики приходит с событием моста; нет — подпись без времени | честно: лента показывает только то, что знают данные | клиентская метка «сейчас» врёт на повторе ленты | брать время прибытия — одно поле, но позже править |
| **[техника]** Глаголы шагов — таблица соответствий в одном месте | read → «Читаю»…, неизвестное — именем | разбор текста строки регэкспами в трёх местах рассыплется | свои формулировки — правка таблицы |
| **[техника]** Формат времени — как в `compare.ts` | «14:32» / «9 окт, 14:32» | одно место знания о времени в окне | свой формат — вторая копия |
| **[техника]** Контракты проверок сохраняются: `feed__row--user`, `step*`, `codeblock*`, `feed-row-details` | класс остаётся на строке вопроса, testid — на ступенях и коде | сценарии (`project_files`, `glavnoe`, снимки) не переучиваются | новые testid — править сценарии |
| **[техника]** Поле `time` в событии моста и состояния `маркдаун`/`прогресс` в фикстуре | кадры снимаются адресом | как `разбор`/`много`; кадры без кликов | снимать кликами в сценарии |
