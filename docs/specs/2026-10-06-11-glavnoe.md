# Главное окно: доводка до образцов

Пункт 11 партии (2026-10-06, круг 1/3). Пункт очереди: **[ui] [этап 2] Довести
главное окно до образцов** (`docs/ROADMAP.md`, «Подробности ближайших пунктов»).

Образцы — два паспорта, оба подтверждены владельцем 2026-10-06:
`docs/refs/главное-окно-тёмная.md` (Codexis) и `docs/refs/главное-окно-светлая.md`
(OpenCode PRO). Слова владельца: «просто хочу, чтобы наше приложение было похоже
на эти скрины (темы одинаковые, отличаются только цвета)»; «пока вообще не похож
на наш концепт». Кадры образцов: `docs/refs/главное-окно-тёмная/target-1.png`
(пустой чат), `docs/refs/главное-окно-светлая/target-1.png` (чат с разбором).

Не входит: окно без рамки (свой пункт очереди), окно настроек (пункт 12),
второстепенные экраны, новые функции «как отдельные системы».

## 1. Зачем экран

Пользователь открывает приложение и видит либо приветственную сборку (чат пуст),
либо разбор своего вопроса (чат с ответом). Одно главное действие — **написать
сообщение модели**: композер всегда на виду внизу центра. Всё остальное
(счётчики, провайдеры, сценарии, правая панель) — обзор и справка, оно тише.

Владелец принимает кадр против «Главного впечатления» обоих паспортов
(было / стало / образец). Значит цель — не «красиво», а «похоже на скрины»:
плотная карточная сборка, две линии в строках, группы по датам, тонкие рамки,
один градиентный акцент.

## 2. Одна раскладка, различие — цвета (решение по словам владельца)

Владелец: «темы одинаковые, отличаются только цвета». Это решает главный спор
паспортов (у каждой темы свой образец-раскладка):

- **Раскладка одна — три колонки** по `docs/DESIGN.md` §5: сайдбар 240 px,
  центр тянется, правая панель 280 px. Отдельную узкую колонку навигации и
  отдельную колонку ленты чатов светлого образца **не заводим**: история чатов
  живёт секциями «Сегодня / Вчера / На этой неделе» в сайдбаре, быстрые
  действия — кнопками шапки сайдбара («+ Новый проект», «Новый чат», «Плагины»).
  Иначе это сетка панелей на весь экран — «не так» по `DESIGN.md` §7.
- **Оба состояния образца — состояния одного экрана:** пустой чат = приветственная
  сборка тёмного образца; чат с ответом = лента со ступенями и код-блоком
  светлого образца. Правая панель живая в обоих состояниях.
- Тема меняет только значения токенов. Ни одна граница, отступ, кегль и порядок
  блоков между темами не различаются (проверяется наложением кадров).

- Сборка стоит в прокручиваемой области ленты, композер прижат к низу — он не
  часть сборки и не едет (существующее поведение). Порядок рядов сверху вниз:
  приветствие (H1 + подзаголовок) → счётчики → провайдеры → сценарии → модели.
- Ряд счётчиков: 4 карточки в ряд; при нехватке источника — меньше (см. §5).
- Ряд провайдеров и ряд моделей: карточек столько, сколько знает продукт;
  ноль известных — ряд не рисуется вовсе (не пустая секция).
- Ряд сценариев: ровно 4 карточки, зазор 12 px, карточка тянется в ряду
  (grid `repeat(4, 1fr)`), вторая строка — подпись.

### 1440×900, чат с ответом (разбор)

Каркас тот же. Центр: шапка чата (как есть) → лента: строка вопроса → ответ
модели: вступление → ступень «1 …» (развёрнута) → ступень «2 …» → свёрнутая
секция «▶ …» с код-блоком внутри → блок «Sources used» (существующий) →
композер. Сайдбар и правая панель — те же.

### 1024×640 — минимум

По `DESIGN.md` §5 (уже сделано в пункте 4 и не меняется): сайдбар 200 px,
правая панель — оверлей 280 px по кнопке `☰`. Сборка перестраивается:

| Что | 1024×640 |
|---|---|
| Ряд счётчиков | 2×2 (перенос по сетке, карточка не сжимается ниже 150 px) |
| Ряд провайдеров / моделей / сценариев | 2×2, затем 1 колонка при ещё более узком окне |
| H1 приветствия | 22 px, переносится на вторую строку |
| Лента, композер, панели | без изменений; подсказка под композером скрывается при высоте < 560 px (решение пункта 4) |
| Код-блок | во всю ширину ленты, длинная строка переносится |

## 5. Настоящие данные (не Lorem ipsum)

Счётчики и ряды рисуются только из того, что продукт знает. Выдуманных чисел,
спарклайнов, трендов и пончиковой диаграммы образца **нет** — данных нет.

| Ряд | Источник | Ноль | Один | Много |
|---|---|---|---|---|
| Счётчик «Чаты» | длина списка чатов | 0 — честно | 1 | «1 284» с разрядом, перенос не ломает строку |
| Счётчик «Проекты» | длина списка проектов | 0 | 1 | — |
| Счётчик «Плагины» | число установленных (реестр) | 0 | 3 | — |
| Счётчик «Вызовы» | сумма счётчиков `usage.json` (пункт 8) | 0 | 1 | — |
| Провайдеры | провайдеры известных моделей (разбор `id` до «/») | ряд не рисуется | 1 карточка: имя + «N моделей» | сколько есть |
| Модели | модель текущего чата + известные | ряд не рисуется | 1 карточка: имя + подпись провайдера | сколько есть |
| Сценарии | константа, 4 карточки (действия реальные, §7) | — | — | — |
| Чаты сайдбара | список чатов + время | «Пока нет чатов» | 1 строка | 100 — группы по датам, скролл, шапка/подвал неподвижны |
| Проекты сайдбара | список проектов | «Пока нет проектов» | вторая линия — путь папки | усечение с «…» + `title` |

Крайние тексты: длинное имя чата (58 знаков) — усечение; вопрос «Ок»; абзац на
400 знаков без пробелов — `overflow-wrap: anywhere`; строка кода на 200 знаков —
перенос внутри код-блока.

## 7. Состав основы (кусок 2 — «без вкуса», по образцам)

**Приветственная сборка центра** — см. §3/§5. Поиск над сборкой (как у образца)
**не заводится** — поиска в продукте нет, а кусок основы его не называет.

**Двухстрочные строки списков.** Вторая линия — только реальные данные:
проект — путь папки; чат — время. Без второй линии — одна линия.

**Группы чатов «Сегодня / Вчера / На этой неделе»** — по локальной дате чата.
Время чата — поле в `appstate` ([техника]); фикстура несёт примерные даты.
Чат без времени — группа «Ранее».

**Код-блок с «Копировать» и подсветкой.** Плашка `--code-bg` в обеих темах,
кнопка «Копировать» видна без наведения; клик — в буфер, подпись 2 с «Скопировано».
Подсветка — `highlight.js` ([техника]).

**Сворачиваемые ступени разбора.** Заголовок Markdown = ступень; номер —
порядковый в сообщении; свёрнутая ступень оставляет заголовок с номером видимым
(проверяемое утверждение светлого паспорта). Развёрнуты по умолчанию; клик —
свернуть/развернуть; `aria-expanded`, фокус с клавиатуры.

**Живая правая панель.**
- *Инструменты:* строки подключённых плагинов чата — имя + кнопки его команд
  (через существующий ход одобрения). Нет подключённых — «Плагины не подключены»
  + «Подключить» (существующий пикер). Строки-заглушки «Терминал — позже»,
  «Файловый менеджер — позже» **удаляются**.
- *Безопасность:* «Доступ к файловой системе» — тумблер: вкл. = папка проекта
  выбрана, значение «Только папка проекта» `--success`; выкл. = «Выключен».
  «Интернет» — тумблер выключен с причиной (`title`): «Своего сетевого состояния
  у чата нет — появится с сетевыми плагинами». Нового права тумблер не выдаёт
  (permission-слой не обходится).

## 12. По чему судить снимок

1. Три колонки 240/280/центр (200/оверлей на минимуме) — по пикселям.
2. Тёмный и светлый кадры совпадают попиксельно по раскладке; отдельной колонки
   чатов нет.
3. Приветственная сборка рядами: H1 → 4 счётчика → провайдеры → 4 сценария →
   модели; вторая линия у карточек; числа полуполужирные, по разрядам.
4. Выдуманных данных нет: ни спарклайнов, ни трендов, ни пончика.
5. «ЧАТЫ» — группы «СЕГОДНЯ / ВЧЕРА / НА ЭТОЙ НЕДЕЛЕ», активный чат —
   единственная акцентная плашка.
6. Акцентных пятен два: «+ Новый проект» и активный чат (+ градиентная кнопка
   отправки и бейдж модели — акцентные элементы образца); логотип, аватар,
   «+» композера, счётчики — приглушённые.
7. Код-блок: тёмная плашка на светлой теме, «Копировать» виден без наведения,
   подсветка токенами, перенос длинной строки.
8. Ступени: номера видны и свёрнутыми; клик сворачивает.
9. Правая панель: команды подключённых плагинов; «позже» нет; у тумблера —
   значение или причина.
10. Ни одного сырого цвета вне tokens.css; теней на панелях нет; лечение
    выбранного варианта видно и совпадает с вырезкой образца.

## 13. Решено за вас

| Что | Решение | Почему | Цена ошибки |
|---|---|---|---|
| **[видно]** Одна раскладка — три колонки; колонку ленты чатов не заводим | история чатов — группами в сайдбаре; действия — кнопки шапки сайдбара | язык владельца «темы одинаковые» + DESIGN §5; иначе «сетка панелей» — §7 запрещает | выделение колонки из секций сайдбара — правка одного компонента |
| **[видно]** Счётчики/провайдеры/модели — только реальные данные | сколько есть — столько карточек; ноль честный | выдуманные числа — ложь интерфейса | правка состава одного ряда |
| **[видно]** Состояния выбранного — как на образце | рамка-акцент у выбранной; бейдж — фон + градиентная рамка | пара паспорта не вошла в список вариантов; на образце этот приём | правка двух CSS-правил |
| **[видно]** Строки «позже» удаляются | панель показывает реальное; «позже» — только отключённое с причиной | кусок основы | вернутся как отключённые строки с причиной |
| **[техника]** Подсветка кода | `highlight.js` (подмножество языков) | самописный — хрупкая система без второго потребителя | снимается одной правкой |
| **[техника]** Markdown-lite в ленте | fenced-код, заголовки→ступени, списки; без зависимости | полный рендер не нужен | сложные ответы отрендерятся частично |
| **[техника]** Группы дат | время чата — поле в appstate/state.json | без времени группам не из чего строиться | чаты без времени — «Ранее» |

| **[техника]** Кнопки панели 24 px, тумблер 32×18, код переносится | §4 не описывает панельные кнопки и тумблер; §6 «не горизонтальный скролл» | плотный характер §1 | правка двух значений |
