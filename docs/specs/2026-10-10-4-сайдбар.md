# Живой сайдбар: двухстрочные чаты, группы дат, поиск (спецификация designer)

Пункт 4 партии 2026-10-09 (круг 1/3). Пункт очереди: **[ui] [этап 2] Живой сайдбар:
двухстрочные чаты, группы дат, поиск** (`docs/ROADMAP.md`, «Подробности ближайших
пунктов»). Вариант выбран владельцем окном: «Живой сайдбар» (2026-10-09).

Образцы, по убыванию веса:

1. Кадр владельца — главный критерий: `docs/refs/главное-окно-светлая/target-1.png`
   (подтверждён 2026-10-06: «одна раскладка, различие — цвета»). Из него пункт
   берёт: колонку чатов с датами, двухстрочные строки, время справа первой линии.
2. Паспорт `docs/refs/главное-окно-светлая.md`, утверждения 4–5: «каждая строка
   списков — две линии: название и подпись/время/состояние», «лента чатов
   сгруппирована по датам».
3. База — нынешний сайдбар: группы дат и время уже на main (`chatGroupOf`/
   `chatTimeOf` в `src/components/Sidebar.tsx`), строка — `SidebarItem`. Пункт
   меняет анатомию строки, добавляет поиск и аватар; группы и подвал не трогает.

Слова владельца: выбрано окном «Живой сайдбар» (2026-10-09). Строк «Замечание
владельца во время партии» и «Не принят» у пункта нет.

Готово, когда: чаты находятся поиском за секунду; группы дат на месте; снимок
против светлого кадра принят. Не входит: переименование чатов, закрепление,
открытие старого чата (переключение сессий — не кусок пункта), горячие клавиши.
Предупреждение разведчика: превью живых чатов — из загруженного списка чатов
ядра; хранилище состояния окна (`WindowState`/state.json, узел «формат
хранения») не расширять.

## 1. Зачем экран

Пользователь находит нужный разговор и узнаёт его за секунду: о чём чат — по
превью последнего сообщения, когда был — по группе дат и времени, каким проектом
занят — по живому аватару. Главное действие одно — **найти и узнать чат**;
поиск — его прямой путь. Всё прочее (новый проект, новый чат, плагины,
статистика, настройки) — второй план: стоит выше списка, но тише списка не
становится. Сейчас сайдбар «неживой»: вторая линия строки — только время,
о содержимом чата не говорит ничего, список в живом окне — одна текущая
строка, искать нечем.

Каркас (DESIGN §5) не меняется: сайдбар 240 px (`--sidebar-w`), 200 px на узком
(`--sidebar-w-narrow`), содержимое 208/168 px. Вертикальный состав колонки:

```

│ СЕГОДНЯ                    │ caps 11 px — группа

│ ▢ Новый чат без вопросов   │ чат без сообщений — ОДНА линия

│ НА ЭТОЙ НЕДЕЛЕ / РАНЕЕ     │

└────────────────────────────┘
```

Поле поиска стоит **над** кнопками — первый контрол после логотипа (кусок:
«сверху сайдбара»; у образца поиск — первый элемент навигационной колонки).
Скроллится только список («Проекты» + «Чаты»), как сейчас: поиск и кнопки на
месте при любой длине истории. На 1024×640 стопка та же — ничего не прячется,
строки усекаются «…».

## 5. Поиск по чатам

Одно поле над кнопками, фильтрует список «Чаты» на клиенте — без задержек и
запросов: сотня строк фильтруется мгновенно (крайний случай «очень много»).

| Что | Как |
|---|---|
| Поле | высота 32 px (минимальная цель нажатия, DESIGN §4), паддинг 8×12 (`--space-2`×`--space-3`), рамка 1 px `--border-strong`, радиус 10 (`--radius-md`), фон `--bg-input`, текст 13 px `--text` — **рецепт готового поиска** `plugin-picker__search`/`catalog-picker__search` (DESIGN §8: сначала найти) |
| Placeholder | `Поиск по чатам…` — называет охват: ищет только чаты, не проекты и не плагины |
| Фильтр | подстрока без регистра по названию **и превью**; превью в данных нет — по названию |
| Группы при поиске | остаются; группа без совпадений не рисуется (как пустая группа сейчас) — дата-контекст строки сохраняется |
| Пустой результат | на месте списка — тихая строка `Ничего не нашлось` 12 px `--text-faint`; секция «Чаты» и поле с текстом и ✕ остаются на местах, ничего не прыгает |
| Совсем нет чатов | «Пока нет чатов» — как сейчас; поиск по пустому списку показывает ту же строку (причина — чатов нет, не «не нашлось») |
| Очистка | ✕ 24×24 справа в поле, видна только при непустом тексте, `title`/`aria-label` `Очистить`; hover `--bg-hover`; Esc очищает текст, повторный Esc снимает фокус (**моё, техника**: стандарт текстовых полей, клавиши пунктом не заводятся — это поведение самого поля) |
| Фокус | обводка 2 px `--accent` с отступом 2 — как у готовых поисков |

## 6. Аватар проекта с состоянием

Кусок 4. Строка раздела «Проекты» получает аватар — букву в квадрате — и точку
состояния: сайдбар отвечает «проект жив?», не открывая панель.

| Что | Как |
|---|---|
| Аватар | квадрат 24×24, радиус 6 (`--radius-sm`), фон `--bg-panel-2`, первая буква имени проекта 12 px / 600 `--text-dim`; зазор до текста 8 (`--space-2`) — анатомия готовой строки с глифом (`sidebar-item__line`) |
| Точка состояния | 8 px, правый нижний угол аватара, кольцо 2 px `--bg-panel`; цвет — статусные токены (DESIGN §2, не акцент): `--success` — папка выбрана и движок отвечает; `--danger` — движок не отвечает |
| Источник честности | тот же `engineDown`, что показывает «Движок — Не отвечает» правой панели и гасит команды меню; своей второй правды о движке сайдбар не заводит |
| Папки нет | строки проекта нет («Пока нет проектов», как сейчас) — аватар и точка не рисуются: нечего помечать |
| Движок не отвечает | точка `--danger`; строка проекта иначе не меняется (кадр `ошибка` показывает красную точку) |
| Не мигает, не кликает | точка — состояние, не действие; строка проекта — вне пункта (не делаем её кнопкой) |

## 7. Живой список: откуда чаты

| Что | Как |
|---|---|
| История чатов | список чатов ядра, загруженный через мост (живые сессии — `GET /api/session`, разбор уже живёт в `session.rs`); мост отдаёт его интерфейсу одним запросом при старте — **техника**: новый метод моста, форма элемента списка знает только Rust (ADR-0001) |
| Состав строки списка | название, время обновления, превью последнего сообщения — **ровно то, что отдаёт список ядра**; превью в списке нет — строки без второй линии (честно; хранилище состояния окна не расширяется — предупреждение разведчика) |
| Активная строка | текущий чат окна (титул/время из состояния окна, как сейчас); его нет в списке ядра — дописывается сверху, в свою группу |
| Совпадение | активной помечается строка, чей титул совпал с текущим; id сессии интерфейс не читает (как и сейчас) — **техника** |
| Клики | активный чат — кнопка (возврат на страницу чата, как сейчас); ряды истории — отображение: не кнопки, без hover и фокуса. Открытие старого чата — переключение сессий, куском пункта не названо |
| Ноль в живом окне | списка нет и текущего чата нет — «Пока нет чатов», как сейчас |
| Счётчик приветствия | `counts.chats` считает реальный список — на «пусто» по-прежнему 0 (честные нули `glavnoe`) |

## 9. Компоненты

Новых компонентов нет: поиск — элемент `Sidebar` (один потребитель), точка и
время — расширения `SidebarItem`.

| Компонент | Правка |
|---|---|
| `Sidebar` / `.css` | поле поиска (§5) над кнопками; прокидывает превью и время в строки; `engineDown` — новый проп из `App` (там уже есть, `data.engineDown`) для точки аватара |
| `SidebarItem` / `.css` | линия 1 собирается в ряд: глиф? + название + `end`? (время, справа); линия 2 — `sub` (превью у чатов, путь у проектов — без изменений); ряды без `onClick` — не кнопки (§7); классы и testid сохранены |
| `app/lists.ts` | слияние: список ядра + активный чат окна; сортировка свежее выше — одно место |
| мост (`bridge`) | метод списка чатов от Rust-моста — **техника**: разбор элемента списка сессий в `session.rs`, интерфейс id не читает; хранение (`state.rs`) не расширяется |
| `fixture.ts`, `viewparams.ts` | дефолтный список 16 чатов (§8); параметр адреса `поиск=<текст>` — предзаполненное поле для кадров (**техника**: как `меню=открыто`) |

## 11. Тексты (дословно)

- placeholder поиска: `Поиск по чатам…`
- очистка: `Очистить` (`title` и `aria-label`)
- пустой результат: `Ничего не нашлось`
- без изменений: группы `СЕГОДНЯ`, `ВЧЕРА`, `НА ЭТОЙ НЕДЕЛЕ`, `РАНЕЕ`;
  `Пока нет проектов`, `Пока нет чатов`, `Этот проект стоил …`; время — вывод
  `chatTimeOf` (`12:57`, `Вчера`, `9 окт`)

## 12. Порядок обхода с клавиатуры

Поиск → ✕ (когда видна) → «+ Новый проект» → «Новый чат» → Плагины →
Статистика → Настройки → строки проектов (остаются как есть — вне пункта) →
активный чат → переключатель темы. Ряды истории и «Ничего не нашлось» фокус не
получают. Esc в поиске — очистка текста, повторный — снятие фокуса (§5).
Остальное окно — без изменений (шапка → лента → композер).

несовпадающие строки ушли, группы пересобрались); ✕ и Esc очищают поле и
возвращают весь список; при пустом результате список заменила одна строка,
поле не сдвинулось; клик по активному чату возвращает на страницу чата.

## 14. По чему судить снимок

1. Сайдбар 240 px: под логотипом поле поиска одной строкой с placeholder
   «Поиск по чатам…»; ниже «+ Новый проект», «Новый чат», Плагины, Статистика,
   Настройки — порядок и вид прежние.
2. Строка чата — две линии: название слева и время справа первой линии;
   вторая линия — превью приглушённым; длинное усечено «…», полный текст —
   в подсказке строки.
3. Группы СЕГОДНЯ / ВЧЕРА / НА ЭТОЙ НЕДЕЛЕ / РАНЕЕ — caps 11 px, пустых групп
   нет; строки внутри группы — свежее выше.
4. Активный чат — единственное акцентное пятно сайдбара: плашка градиентом,
   обе линии светлые; время и превью на нём читаются.
5. Чат без сообщений — одна линия (название + время), пустой второй нет.
6. Аватар проекта: буква в квадрате 24 px, точка состояния зелёная; на кадре
   «ошибка» — красная; точка — статусный токен, не акцент, не мигает.
7. Поиск (`поиск=модел`): остались только совпадения, группы без совпадений
   скрыты; поле с текстом и ✕ на месте.
8. Пустой результат (`поиск=ффф`): на месте списка одна строка «Ничего не
   нашлось»; поиск, кнопки и подвал не сдвинулись.
9. 1024×640: сайдбар 200 px, поиск вмещается, строки усечены «…», скролл
   списка вертикальный; у «много» все четыре группы на месте.
10. Тёмный и светлый кадры совпадают по раскладке, различие — токены; ни одного
    сырого цвета вне `tokens.css`; «пусто» — «Пока нет чатов» и нули сборки.

| Что | Решение | Почему | Чем обойдётся, если неверно |
|---|---|---|---|
| **[видно]** Поиск стоит под логотипом, над кнопками, и ищет только чаты | первое поле сайдбара, placeholder называет охват | кусок: «поиск по чатам сверху сайдбара»; у образца поиск — первый элемент колонки | перенести поле к секции «Чаты» — один блок в `Sidebar.css` |

| **[видно]** Время переехало на первую линию вправо, вторая линия — превью; у чата без сообщений второй линии нет | анатомия строки образца | кусок 2 называет имя, превью и время; образец: время справа первой линии | время второй линией — вернуть старый рендер `sub` |
| **[видно]** Ряды истории — не кнопки: без hover и фокуса; кликаются активный чат и навигация | честный сигнал «нажать нельзя»; открытие старого чата — не кусок пункта | мёртвая кнопка врёт руками; «Не входит» не исключает переключение сессий, но и не требует | вернуть кнопкам `onClick`-заглушку, когда дойдёт до переключения сессий |
| **[видно]** Аватар проекта — буква в квадрате с точкой состояния (`--success`/`--danger` по `engineDown`) | «состояние» — статусные цвета DESIGN §2; источник тот же, что у «Не отвечает» панели | кусок называет аватар с состоянием; второй правды о движке не заводим | другая семантика точки — правка одного пропа-тонала |
| **[техника]** Список живых чатов — из загруженного списка ядра одним запросом; `WindowState`/state.json не расширяется | предупреждение разведчика: «формат хранения» — общий узел | превью и время — свойства списка сессий, не состояния окна | расширить state.json — правка контракта хранения |

## 17. Проверки, которых коснётся

Исполнителю: сценарии и кадры, держащие нынешнее поведение.

- `glavnoe` — группы (все четыре) и «двухстрочность» активного чата на
  «много»: `.sidebar-item__sub` теперь превью, проверка читает тот же класс;

- `window_shot` — главные кадры обагатятся сайдбаром (дефолт теперь 16 чатов);
  новые кадры поиска и «много» на 1024; ожидания текстов главных кадров
  («Новый чат») не тронуты.
- `window_look` — пятно `chat-active` на месте; ширины сайдбара 240/200 без
  изменений; проверка прокраски («пилюля темы») не задета.
- `settings`, `plugin_config`, `plugins_section`, `stats_page`, `stats_shot`,
  `usage_shot` — клики по `chat-active` и входам сайдбара живут.
- `new_chat`, `full_cycle` — после «Нового чата» активной строки нет, список
  остаётся; перезапуск сессии не задет.
- `no_raw_colors` — точка состояния, поиск и их состояния через токены.
