# Концепция

Начало файла до первой черты — бриф на одну страницу: его читают перед любой
правкой поведения, из его разделов `/studio/roadmap` берёт системы для «Покрытия
замысла» `ROADMAP.md`. Сказанное владельцем и предположенное различать:
догадка помечается `[допущение]`. Полные спеки — `docs/SPEC/` (плагины, Фаза 2).

## Одной строкой

GnomeCode — «Идеи. Код. Результат.»: десктопный ИИ-партнёр в разработке для
Windows — чат с моделями поверх ядра OpenCode, привязанный к проектам, с
плагинами «в два клика» и безопасностью на уровне чата.

## Ядро

Главные сценарии пользователя:

1. Открыть проект (папку) и спросить модель, дав ей контекст файлов —
   ответ стримится, вызовы инструментов видны в ленте строками.
2. Подключить плагин из чата: «+» → Connect plugin → сразу работает
   (кнопка в шапке, клик исполняет команду) — без конфигов и перезапуска.
3. Продолжать работу над одной темой через много чатов: проект помнит
   знания, задачи и результаты (Workspaces, Tasks, Artifacts — Фаза 2).
4. Доверять работе: права у каждого плагина видны и ограничены политикой
   чата; крупная правка — checkpoint с откатом.
5. Накапливать приёмы: удачный воркфлоу становится Skill, который AI
   находит сам в следующий раз (Фаза 2).

## Цель и провал

Пользователь доводит задачу (фича, фикс, ассет, документ) до результата:
принятая правка, собранный проект, готовый файл — и результат остаётся
Артефактом проекта. Уходит ни с чем честно: когда нет нужного Skill,
плагина или права, GnomeCode говорит это прямо (Capability Discovery), а не
прикидывается умеющим.

## Первая версия

Для себя и разработчиков-ранних пользователей: проверить связку «Tauri +
OpenCode» и принцип «плагин в два клика». Глаголы, с которыми «это моё»:
спросить модель с контекстом проекта, подключить плагин из «+», увидеть
вызов инструмента в ленте, принять результат. `[допущение]` — не спрашивали
отдельно, следует из заметок и спек владельца.

- macOS/Linux в первой версии — сказали вы: «Windows сначала».
- Веб-версия и мобильные — `[допущение]`: десктоп по референсам.
- Generic IDE-dashboard: философия раскладки референсов сохраняется

## Вид

Только экраны: `docs/DESIGN.md`. Референсы — тёмная тема (основа) и светлая,
равноправные; иконка/логотип — гном-разработчик. Карта образцов —
`docs/refs/INDEX.md` (референсы ждут файлов владельца).

# Ограничения

## Технические требования

- Windows 10/11 x64 — первая платформа (сказали вы).
- Ядро требует установленного OpenCode (`opencode` в PATH) и ключей
  провайдеров у пользователя; без них GnomeCode работает как интерфейс без моделей.
- Данные пользователя — в `%APPDATA%/GnomeCode`; проверки гоняются на
  отдельной папке (`GNOMECODE_DATA_DIR`).
- Экономия контекста — архитектурное требование (Фаза 2, раздел 14):
  retrieval, не заливка.
- Секреты (ключи моделей, токены плагинов) — только в хранилище ОС, не в
  репозитории.

# Архитектура

Правило, а не рассказ: по нему судит `reviewer` («Правила кода» `AGENTS.md`).
Место системы — модуль или папка, не один файл: «всё X в одном файле» сюда не
писать. «Где что» и «Копии» пополняет `/studio/done` из строк итога исполнителя «В
документы при /studio/done: CONCEPT, …».

Слои: UI (React-компоненты) не знает про HTTP и OpenCode; сервисы
(TS-модули: реестры плагинов/скиллов, состояние) зовут API-клиент;
API-клиент (`src-tauri/`, Rust) — единственное место, которое знает про
OpenCode server и файловую систему; permission-слой между сервисами и любым
tool-вызовом.
Новая система: `src/features/<система>/` (UI+сервис) и при необходимости
`src-tauri/src/<система>/` (мост); корневой компонент только собирает.
Содержимое: знания и скиллы — Markdown с frontmatter в папке данных
workspace; реестр находит папку сам (спека Фазы 2, раздел 12).
Службы (автозагрузки): нет; новая — только строкой сюда.
